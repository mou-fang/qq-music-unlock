# QQ Music Unlock

一个尽量简单、开箱即用的 **QQ 音乐本地文件解锁工具**。

项目只保留 QQ 音乐相关功能，不包含网易云音乐或其他平台。对于旧版 QQ 音乐加密格式，文件可以直接在浏览器中处理；对于新版 `musicex` 格式，则需要与该歌曲对应的 **EKey**。

> 在线完整版：**https://moufang.xyz/#/music**
>
> 如果你手里的是新版 `.mflac` / `.mgg`，又不知道如何获得 EKey，推荐直接使用上面的完整版。

---

## 主要特点

- 无需安装 Node.js、npm、Python 或桌面客户端
- 下载仓库后直接打开 `index.html` 即可使用
- 支持拖拽文件和多文件处理
- 解锁完成后直接在浏览器下载输出音频
- 只处理本地文件，旧格式解密不需要上传音频文件
- 仅保留 QQ 音乐相关格式，项目结构非常小
- 新版 `musicex` 支持手动输入 EKey
- README 中直接提供 Moufang 网站完整版入口

## 支持格式

当前页面面向以下 QQ 音乐加密格式：

- `.mflac`
- `.mgg`
- `.qmc0`
- `.qmc2`
- `.qmc3`
- `.qmcflac`
- `.qmcogg`
- `.tkm`
- `.bkcmp3`
- `.bkcflac`
- `.tm0`
- `.tm2`
- `.tm3`
- `.tm6`

需要注意：**扩展名相同并不代表内部加密结构一定相同。**

例如 `.mflac` / `.mgg` 既可能是较老的、文件内部已经保存了可用于解密的信息，也可能是新版 `musicex` 文件。工具会根据文件尾部结构判断实际格式，而不是只根据扩展名猜测。

# 为什么有些旧文件可以直接解锁？

QQ 音乐历史上使用过多种不同的本地加密格式。

本项目目前识别的主要路径包括：

1. **QMCv1 静态密钥格式**
   - 例如部分 `.tkm`、`.bkcmp3`、`.bkcflac`
   - 解密所需规则本身是固定的
   - 文件不需要额外向 QQ 音乐服务器请求密钥

2. **V1 keyed 格式**
   - 文件尾部保存了用于派生解密密钥的数据
   - 解密所需信息已经包含在文件中

3. **QTag / STag 格式**
   - 文件尾部会携带 EKey 或与 EKey 相关的数据
   - 因为密钥信息跟文件一起保存，所以浏览器可以直接从文件中读取并解密

这些旧格式的共同点是：

> **仅凭本地文件本身，就可以取得足够的解密信息。**

因此它们不需要 QQ 登录账号，也不需要调用 QQ 音乐在线接口。

# 为什么新版 `.mflac` / `.mgg` 需要 QQ 音乐账号？

这是新版 QQ 音乐 `musicex` 文件与旧格式最重要的区别。

新版 `musicex` 文件通常仍然包含加密后的音频数据，以及歌曲标识、文件名等尾部信息，但是：

> **真正用于解密音频的 EKey 不再直接完整地保存在本地文件中。**

也就是说，程序即使已经拿到了整个 `.mflac` / `.mgg` 文件，也只能知道“这是什么歌曲、音频数据在哪里”，却缺少完成解密所需的关键密钥材料。

这时就必须根据文件中的歌曲信息，向 QQ 音乐的在线接口请求该歌曲对应的 **EKey**。

而 QQ 音乐不会无条件给任何请求返回可用的 EKey。这个请求与当前 QQ 音乐登录账号的权限有关，因此完整版需要使用一个有效的 QQ 音乐登录状态。

整体过程可以简单理解为：

```text
新版 .mflac / .mgg
        │
        ├─ 读取文件尾部
        │    └─ 得到歌曲标识 / musicex 信息
        │
        ├─ 使用 QQ 音乐登录账号请求该歌曲的 EKey
        │
        ├─ 从 EKey 派生真正的解密密钥
        │
        └─ 在浏览器中解密音频数据
             └─ 输出 FLAC / MP3 / OGG 等正常音频
```

所以，“需要账号”并不是因为这个网页本身想强制用户登录，而是因为 **新版文件没有把完整解密密钥直接留在文件里，必须通过 QQ 音乐在线服务取得对应 EKey。**

# 为什么登录的账号必须能播放 / 下载这首歌？

这是使用新版文件时非常重要的一点。

QQ 音乐返回歌曲资源和相关密钥时，会根据账号当前拥有的内容权限进行判断。权限可能受到很多因素影响，例如：

- 是否为 QQ 音乐会员
- 是否拥有该歌曲所需的会员等级
- 是否购买过数字专辑或单曲
- 该歌曲当前是否允许该账号播放
- 该音质是否属于账号当前可使用的音质等级
- 地区、版权状态或歌曲上下架状态
- 账号是否仍然拥有原来下载该文件时对应的访问权限

因此，用来获取 EKey 的账号必须对目标歌曲拥有有效权限。

最简单的判断方法就是：

> **这个账号在 QQ 音乐官方客户端中，应该能够正常播放，并且在对应权限条件下能够下载这首歌。**

如果一个文件原本是用账号 A 下载的，但你现在登录账号 B，而账号 B 没有这首歌曲或对应音质的播放/下载权限，那么 QQ 音乐接口可能：

- 不返回有效 EKey
- 返回的资源权限不足
- 返回与该文件不匹配的密钥信息
- 最终导致解密后的文件头无效，无法还原出正常音频

所以新版文件出现“有账号但还是解不开”的情况时，首先要确认的不是解密算法，而是：

1. 当前登录的是不是正确的 QQ 音乐账号；
2. 这个账号现在是否还能正常播放这首歌；
3. 这个账号是否拥有对应会员 / 已购内容权限；
4. 对于高音质文件，账号是否拥有该音质等级的访问权限。

**账号能登录，不等于账号对这首歌曲有解密所需的资源权限。**

# 为什么不能直接用一个“公共账号”给所有人解锁？

因为 EKey 的获取本质上仍然受 QQ 音乐账号权限控制。

一个普通账号并不一定拥有所有歌曲、所有数字专辑、所有会员内容以及所有音质等级的访问权限。即使某个账号可以获取歌曲 A 的有效 EKey，也不代表它可以获取歌曲 B 的有效 EKey。

另外，账号权限、歌曲版权状态、会员状态和服务端接口都可能发生变化。

因此这个项目不会声称存在一个“万能账号”或“万能 EKey”。

# 技术说明

当前解密核心会根据文件尾部识别不同路径，包括：

```text
musicex
QTag
STag
V1-keyed
V1-static
```

对于包含 EKey 的格式，会进一步经过密钥解析 / 派生，然后根据实际密钥和文件情况使用相应的 QMC 解密流程。

新版 `musicex` 是特殊情况：

```text
文件内没有可直接使用的完整 EKey
        ↓
需要 QQ 音乐服务端根据账号权限返回 EKey
        ↓
本地解密核心才能继续生成真正的音频数据
```

这也是为什么本项目没有简单地把“账号登录”从新版流程里删除——删掉登录并不会让新版文件凭空获得缺失的 EKey。

# 常见问题

## 1. 为什么我的 `.mflac` 有的能直接解，有的不能？

因为 `.mflac` 只是扩展名。

旧版 `.mflac` 可能采用 QTag 等结构，EKey 已经包含在文件里；新版 `.mflac` 可能采用 `musicex`，需要额外从 QQ 音乐获取 EKey。

## 2. 我已经登录 QQ 音乐了，为什么还是解不开？

请确认这个账号本身可以正常播放 / 下载对应歌曲，并拥有该文件对应音质需要的权限。

“登录成功”只说明账号身份有效，不代表该账号拥有每一首歌曲的内容权限。

## 3. VIP 账号是不是一定能解所有文件？

不是。

歌曲版权、数字专辑购买状态、会员等级、音质权限、地区限制等都可能影响结果。

## 4. 为什么不把 Cookie 直接写进这个 GitHub 项目？

因为 Cookie 属于登录凭据，不应该提交到公开仓库，也不应该硬编码在前端源码中。

## 5. 可以批量处理吗？

可以。页面支持一次选择多个文件，并依次处理。

## 6. 文件会上传到 GitHub 吗？

不会。GitHub 仓库只托管网页源码。你拖入页面的音乐文件由浏览器本地读取。
